# Synthetic data without an insulated benchmark

Status: recommendation for discussion, 2026-09-09. Synthetic authorization is
approved; the wider final training mixture remains open. Current generated data
are implementation fixtures only.

**Updated recommendation after reviewing existing corpora:** use an established
ordinary-text corpus alongside generated authorization tasks. Audit a
source-selected Common Pile sample first and compare FineWeb-Edu if needed.
[DATASET_SHORTLIST.md](DATASET_SHORTLIST.md) records the evidence, inspection
snapshots, and selection criteria. This supersedes the provisional preference
below for a wholly programmatic claim-bearing pilot; programmatic fixtures remain
appropriate for implementation and early debugging. No final corpus is frozen.

## What control buys, and what it does not

Programmatic generation gives us exact task definitions, ground-truth answers,
reproducible distributions, and the ability to vary one cause at a time. It does
not guarantee that the distribution contains pressures relevant to a deployed
language model. A billion examples from one narrow generator can preserve the
same blind spot a billion times.

Two different meanings of synthetic must be distinguished:

1. **Programmatically generated tasks.** We write a symbolic world or procedure,
   execute it to get the answer, and render inputs. No external model supplies
   the dataset's answers. This is the proposed starting point.
2. **Text generated by an existing language model.** We can preserve its prompts
   and outputs, but the teacher contributes capabilities and biases derived from
   its training history. That is not an independently controlled data lineage.

For example, TinyStories demonstrates useful small-model learning with synthetic
stories, but its stories were produced by GPT-3.5/GPT-4. It does not establish
that an entirely programmatic world provides the same language-learning coverage.
[TinyStories](https://arxiv.org/abs/2305.07759).

Codex can assist in writing and auditing generator code, as here. That is a
tool-assisted research process, not independence from all external ideas or
software. Record that assistance; distinguish it from using a pretrained teacher
to produce the training examples or reference answers.

## The pressures the pilot should contain

The following are proposed requirements for the final mechanism experiment,
not features already implemented in the version-0 fixture generator:

| Possible blind spot | Test or control |
|---|---|
| Remembering templates or names | Change representations, names, record order, and surface grammar while preserving the latent problem |
| Memorizing familiar combinations | Hold out combinations of known operations; separately test moderately greater depth or length |
| Using a superficial permission cue | Balance permitted and forbidden cases; vary equivalent permission representations and include irrelevant distractors |
| Mistaking an output-format failure for lost competence | Evaluate the useful answer directly in formats without the protected convention |
| Defining all capability through the protected task | Train and measure several capability families separately, such as arithmetic, symbolic execution, and composition |
| Sharing one generator's bugs across all tests | Write a separately implemented challenge suite, verify it with hand-worked fixtures, and reserve it from defense tuning |
| Calling indiscriminate refusal safety | Require correct permitted answers alongside withholding forbidden answers |
| Calling optimization brittleness coupling | Require successful benign edits and attacks explicitly preserving or recovering useful skills |
| Protecting only against the training attacker | Reserve an attack family and include conditional/final-layer bypasses early in development |

A held-out random seed tests new instances from substantially the same world.
It is not, by itself, a test of new structures or different worlds. SCAN is an
example of a controlled task exposing failures of compositional generalization:
[Lake and Baroni](https://www.cs.princeton.edu/~bl8144/papers/LakeBaroni2018ICML.pdf).
Procgen offers an analogous lesson about distribution diversity in reinforcement
learning, not direct evidence about SCC:
[Cobbe et al.](https://arxiv.org/abs/1912.01588).

The new pressures must still be learnable by the controls. A challenge on which
all intact models start at chance cannot establish attack-induced capability
loss. Measure clean competence on each evaluated domain before interpreting an
attack comparison. Do not tune against the final challenge suite; if it reveals
a design flaw, report the result and use a new reserved suite for later claims.

## Proposed direction within $450

Start with programmatic tasks for infrastructure and mechanism discovery. Keep
the data interface capable of accepting both tasks and manifested text documents.
Avoid buying a large teacher-generated corpus or spending the budget training a
general conversational model before establishing the mechanism.

Before the nine-model campaign, decide between two explicit scopes:

- **Fully programmatic mechanism pilot:** stronger structural and attack stress
  tests, with a claim restricted to the measured synthetic capability families.
  Natural-language transfer remains a funded follow-up. This is my provisional
  recommendation if independent data lineage is the overriding constraint.
- **Language-model pilot with synthetic authorization:** a documented ordinary
  text component plus the controlled tasks. We still initialize all weights
  ourselves and preserve data provenance. Using public text does not surrender
  control of the model's training history, but brings corpus selection and reuse
  obligations and a broader distribution to learn.

An external natural-text evaluation alone does not repair missing language
training. If a fully programmatic model cannot perform it before attacks, that
evaluation is a boundary finding rather than a meaningful capability-retention
test. A claim of relevance to ordinary language models ultimately needs a model
that demonstrates the relevant ordinary-language competence.

A successful synthetic pilot can justify funding that transfer test. It cannot
claim transfer has already occurred. Generator diversity, architectural choices,
and ordinary checkpoint redundancy may all change the result at the next stage.

The earlier pilot proposal includes held-out natural-language modeling in its
capability suite. Choosing a wholly programmatic final campaign would explicitly
revise that component and narrow the claim; this document does not treat that
revision as already approved.
